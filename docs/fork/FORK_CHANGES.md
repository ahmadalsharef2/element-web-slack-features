# Fork changes

A record of what this fork (Element Fork) adds on top of upstream Element Web, so our work can be told apart from
upstream's when merging. Upstream is the `develop` branch of element-hq/element-web. Everything below was added on
`slack-features-cleanup`.

New files carry a `Copyright <year> Ahmad` header. To find our work from the code:

```sh
git diff --stat develop...HEAD                 # every file the fork touched
git grep -l "Copyright 20.. Ahmad"              # files that are entirely ours
git grep -n "Element Fork:"                     # comments marking our changes inside upstream files
```

Other changes to behaviour:

- **Fewer languages.** Only English, German, French, Spanish, Italian, Dutch, Polish, Brazilian Portuguese, Finnish,
  Russian, Ukrainian, Japanese, Hebrew and Chinese (simplified and traditional) are kept in `i18n/strings` of
  `apps/web`, `apps/desktop` and `packages/shared-components`. Upstream has no Arabic or Luxembourgish.
- **Threads** are reached from the room header. The bottom-of-bar overview across all rooms and the Developer tools
  shortcut from the old gear menu are gone (`/devtools` still works).

- **Your read receipts are private by default.** `sendReadReceipts` in `Settings.tsx` defaults to off, so others don't
  see that you have read their messages (a private receipt is sent instead). You still see other people's receipts
  (`showReadReceipts` keeps the upstream default of on). An account that already has `sendReadReceipts` on keeps it:
  turn it off under Settings → Preferences → "Send read receipts". The choice also holds while the check for server
  support is still running or has failed; upstream sends public receipts until that check succeeds.
- **"Share my online status" is kept per device and applies from the first sync.** `sharePresence` is a device
  setting, so it is known at start-up before the account settings load, and `MatrixClientPeg.start()` sets the
  presence to offline before the first sync is sent. Turn it off once on each device.
- **Scheduled messages are sent by the homeserver when it can.** With delayed events (MSC4140) on the server and an
  unencrypted room, `utils/scheduledMessages.ts` hands the message to the server, which sends it even if Element is
  closed or offline. Encrypted rooms and servers without MSC4140 keep the browser-only queue, which sends only while
  Element is open. The schedule dialog says which applies to each message.

### Repository changes that are not features

Upstream CI workflows, issue templates, release tooling, git hooks, unused docs and scripts were removed. The fork
plan is in [ENHANCEMENT_PLAN.md](ENHANCEMENT_PLAN.md).

Also removed, as they only ran in upstream's CI or were never loaded:

- The upstream Playwright e2e suite. Only our `composer/schedule-send.spec.ts`, the UX harness in `ux/` and the
  helpers they reach remain.
- All screenshot baselines (`apps/web/playwright/snapshots/`, `packages/shared-components/__vis__/`).
- The optional runtime modules in `modules/` (none was configured), with their workspace, knip and patch entries.
- The desktop `CHANGELOG.md` and the `jsqr` and root `@typescript/native` dev dependencies.
